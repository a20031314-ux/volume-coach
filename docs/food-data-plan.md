# 음식 데이터 확장 계획

> 2026-11-07 정리. 지금 내장 음식 127종(`src/lib/foods.ts`)에서 "사람들이 실제로 먹는 것"까지 넓히는 방법.

## 1. 지금 상태
- 127종: 단백질 재료·주식·과일·채소·지방·유제품·대표 외식 20여 개·간식.
- **잘 잡히는 것:** 헬스 식단 재료. 식단 추천·대체 식단은 이 재료만 쓰므로 지금 데이터로 충분.
- **비어 있는 것:** 반찬·국(계란말이, 나물, 미역국…), 외식(볶음밥, 카레, 초밥, 마라탕, 탕수육, 갈비…), 편의점(도시락, 컵라면, 제품별 닭가슴살), 카페·술, 빵·과자.
- 체감 커버율(추정, 실측 아님): 헬스인 기록 약 70%, 일반 한국인 하루 식사 약 50%.

## 2. 데이터가 있는 곳 (수집 가능 범위)

| 종류 | 예 | 출처 | 수집 방법 | 정확도 |
|---|---|---|---|---|
| 재료·일반 메뉴 | 닭가슴살, 김치찌개, 계란말이 | 식약처 식품영양성분DB 통합 자료집(자주 먹는 음식 548품목, 가공식품·원재료 제외) | 파일 1회 정리 → 앱 내장 | 표준 레시피 기준, 실제와 ±20~30% |
| 포장 가공식품 | 신라면 1봉, 햇반, 브랜드 닭가슴살 | 식약처 전국통합식품영양성분정보(가공식품) 표준데이터 — 제품명·제조사·1회 섭취참고량·중량·영양성분 23종·품목제조보고번호, 연 1회 갱신 | 파일·API 일괄 → Supabase 테이블 | 포장 표시 기준(리뉴얼 시 늦게 반영) |
| 대형 프랜차이즈 | BBQ 황금올리브, 교촌, 맥도날드, 도미노, 스타벅스 | 업체 홈페이지 공개(통합 API 없음, 미공개 브랜드도 있음) | 공개 표를 보고 직접 정리, 출처·확인일 저장 | 업체 공개값 |
| 동네 식당·집밥 | 엄마표 제육, 동네 국밥 | 없음 | 일반 메뉴 평균값 또는 AI 추정 | ±20~30% |

- 프랜차이즈는 브랜드 차이가 큼: 한국소비자원 조사에서 치킨 1마리 1,554~3,103kcal, 단백질 128~175g → "후라이드 치킨" 평균값 하나로는 부족.
- "절반", "3조각"은 단위만 맞추면 계산 가능(지금 구조: 단위 + step, 예: 마리 0.5 단위).
- **쓰면 안 되는 것:** 다른 칼로리 앱(팻시크릿, 다이어트신 등)의 DB — 출처 불명·권리 문제.
- **확인 필요:** 식약처 데이터의 공공누리 유형(상업 이용·출처 표시 조건), 프랜차이즈 사이트 이용약관(자동 크롤링 대신 수작업 정리 권장).

## 4. 진행 순서
1. **재료·메뉴 300개 내장** (식약처 음식 DB 기준, 반찬·국·외식·편의점·음료 위주). 서버·방침 변경 없음, OTA. → 바로 가능
2. **가공식품 DB → Supabase** 테이블 + 검색. 자주 쓰는 제품은 폰에 캐시(검색은 온라인 필요). 저장량 수십 MB 이내(무료 500MB 안). 방침에 "음식 검색어 서버 전송" 한 줄. → 사용자가 data.go.kr에서 파일을 받아 첨부하면 정리·업로드 스크립트 작성
3. **프랜차이즈 대표 메뉴** 200~300개: 치킨 10개 브랜드 → 버거 → 피자 → 카페 → 편의점 도시락. 출처·확인일 필드 추가
4. **AI 추정**(7번 기존 계획): 위에서 못 찾은 것만, "AI 추정" 표시·수정 가능
5. 출시 후: 운영자 통계로 "직접 입력 많은 음식" 확인 → 추가
