# Google Play 출시 가이드 (볼륨 코치)

개인 개발자 계정 기준. 위에서부터 순서대로 하면 됩니다. `[ ]`는 직접 할 일.

## 0. 먼저 정할 것
- [ ] **개인정보처리방침 운영자 이름·문의 이메일**: `src/content/privacy.json`의 `[운영자 이름]`, `[문의 이메일]`, `[Supabase 리전]`을 채우고 `npm run privacy` 실행 → `docs/privacy/index.html` 갱신
- [ ] **개인정보처리방침 공개 주소** 만들기 (둘 중 하나)
  - GitHub Pages: 저장소 → Settings → Pages → Branch `main`, 폴더 `/docs` → 저장. 주소는 `https://a20031314-ux.github.io/volume-coach/privacy/` (저장소가 비공개면 Pages가 유료일 수 있음)
  - 또는 Notion·Google Sites 등에 같은 내용을 공개 페이지로 게시
- [ ] 주소가 생기면 `src/lib/links.ts`의 `PRIVACY_URL`에 넣기 (앱의 설정 → 앱 정보 → 개인정보처리방침 → "웹에서 보기")
- [ ] 위치정보법 확인 (KISA 위치정보지원센터 또는 전문가): 로그인 시 러닝 경로가 서버에 저장됨
- [ ] Open-Meteo(고도·날씨) 상업 이용 여부 결정

## 1. 앱 만들기
Play Console → **앱 만들기**
- 앱 이름: `볼륨 코치` · 기본 언어: 한국어 · 앱 · 무료
- 개발자 프로그램 정책·미국 수출 법규 동의

## 2. 정식 빌드(AAB) 만들기
```powershell
git pull
git status            # package-lock.json이 바뀌었으면: git checkout -- package-lock.json
npm run build:android:store
```
- `production` 프로필로 **AAB**(app-bundle)가 만들어집니다. 테스트용 APK와 같은 서명 키를 씁니다.
- 끝나면 expo.dev → Builds에서 `.aab` 파일을 내려받습니다.
- 정식 앱의 코드 업데이트는 `npm run update:prod`로 보냅니다 (테스트 앱은 지금처럼 `npm run update`).

## 3. 비공개 테스트 (필수: 테스터 12명 × 14일)
Play Console → 테스트 및 출시 → **테스트 → 비공개 테스트** → 트랙 만들기
- [ ] 테스터: 이메일 목록 또는 Google 그룹. **12명 이상**이 참여(옵트인)한 상태로 **14일 연속** 유지되어야 정식 출시 신청 가능
- [ ] 새 버전 만들기 → **Play 앱 서명** 기본값 사용(Google이 앱 서명 키 관리, EAS 키는 업로드 키가 됨) → AAB 업로드
- [ ] 출시 노트 예: `첫 테스트 버전입니다.`
- [ ] 테스터에게 참여 링크 공유 → 테스터가 링크에서 "테스터 되기" 후 Play 스토어에서 설치
- 테스트 기간 중 코드 수정은 `npm run update:prod`로 바로 반영됩니다(새 빌드 불필요한 경우)

## 4. 앱 콘텐츠 (정책 → 앱 콘텐츠)
| 항목 | 답변 |
|---|---|
| 개인정보처리방침 | 0번에서 만든 주소 |
| 앱 액세스 | **모든 기능을 별도 제한 없이 이용 가능** (로그인은 동기화용 선택 기능) |
| 광고 | 광고 없음 |
| 콘텐츠 등급 | 설문 → 카테고리 "기타/유틸리티"에 가까움. 폭력·성·도박·사용자 간 소통 없음 → 전체이용가 예상 |
| 타겟층 | **만 18세 이상** 권장 (아동 대상 아님 → 가족 정책 적용 안 받음) |
| 뉴스 앱 | 아님 |
| 건강 앱 | 해당. 카테고리: **활동 및 피트니스**, **영양 및 체중 관리** |
| 헬스 커넥트 권한 | 아래 4-1 |
| 데이터 보안 | 아래 4-2 |
| 위치 권한(백그라운드) | **해당 없음** — 앱이 `ACCESS_BACKGROUND_LOCATION`을 요청하지 않음 |
| 정부 앱 / 금융 기능 | 해당 없음 |

### 4-1. 헬스 커넥트 권한 신고
- 요청 권한: `READ_STEPS`(걸음 수), `READ_DISTANCE`(거리)
- 사용 목적 예시:
  > 사용자가 연결을 켠 경우, 하루 걸음 수와 걸은 거리를 읽어 기록 탭의 하루 활동 타임라인(15분 단위 걸음 막대)과 하루 총 활동량·칼로리 추정에 표시합니다. 읽은 데이터는 기기 안에서만 처리하며 서버로 전송하거나 제3자에게 제공하지 않습니다.
- 앱 안의 권한 설명: 설정 → 걸음 수 화면, 개인정보처리방침 1·3항

### 4-2. 데이터 보안 양식
기본 질문
- 데이터 수집·공유: **예**
- 전송 중 암호화: **예** (HTTPS)
- 삭제 요청 방법: **예** — 앱 안 계정 삭제 + 문의 이메일. "계정 삭제 URL" 칸에는 개인정보처리방침 주소(5항에 삭제 방법 안내)를 넣음

수집 항목 (가입·동기화를 켠 경우 서버에 저장되는 것 기준)
| 데이터 유형 | 수집 | 공유 | 필수/선택 | 목적 |
|---|---|---|---|---|
| 위치 → 정확한 위치 | 예 | 예(Open-Meteo: 고도·날씨 계산용 좌표) | 선택 | 앱 기능 |
| 개인 정보 → 이메일 주소 | 예 | 아니요 | 선택 | 계정 관리 |
| 건강 및 피트니스 → 건강 정보(체중·체지방 등) | 예 | 아니요 | 선택 | 앱 기능 |
| 건강 및 피트니스 → 피트니스 정보(운동 기록) | 예 | 아니요 | 선택 | 앱 기능 |

- 헬스 커넥트·건강 앱에서 읽은 걸음 수는 **기기에서만 처리**하므로 수집 항목에 넣지 않아도 됨 (Play 기준: 기기 밖으로 나가지 않는 데이터는 수집 아님)
- 분석, 광고 ID, 기기 ID, 사진, 연락처: 수집 안 함
- Open-Meteo 좌표 전송을 "공유"로 표시한 것은 보수적인 선택. 서비스 제공자 예외로 볼 수도 있지만 표시해 두는 편이 안전함

## 6. 정식 출시 신청
- 비공개 테스트 14일이 지나면 대시보드에 **프로덕션 액세스 신청**이 열림 → 테스트 중 받은 피드백, 수정 내용 등 설문 작성 → 승인 후 프로덕션 트랙에 출시

## 7. (선택) 자동 제출
- Google Cloud 서비스 계정 JSON을 만들어 EAS에 등록하면 `npx eas-cli@latest submit --platform android --profile production`으로 업로드 가능. **첫 업로드는 Play Console에서 직접** 해야 함
