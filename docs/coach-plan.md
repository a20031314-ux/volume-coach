# 목표·코치 엔진·MY 탭 설계

> 2026-11-07 정리. 구현 전 설계. 옵션을 늘리면서도 화면은 단순하게 유지하는 구조.

## 1. 원칙
- 옵션은 **바뀌는 빈도**로 둘 곳을 나눈다.
  | 종류 | 예 | 위치 |
  |---|---|---|
  | 방향(거의 안 바뀜) | 몸 방향, 시간 비중, 경력, 루틴/규칙 | MY 탭 목적 카드 |
  | 오늘(그날만) | 컨디션, 다른 날, 치팅, 오늘만 스트레칭 | 각 탭 조정 시트 |
  | 취향(가끔) | 단위, 음성, 그래프 범위, 알림 시간 | 그 기능 화면의 "⋯" (MY 세부 설정엔 바로가기) |
- **프리셋 + 직접 바꾸기**: 사용자는 큰 값만 고르고, 세부 값은 거기서 계산된다. 화면에는 손잡이가 아니라 결과값을 보여 준다. 직접 바꾼 값은 "직접 설정" 표시 + 추천으로 되돌리기.
- **관련 있을 때만 보이기**: 치팅데이는 감량·리컴프·유지일 때만, 중량 프로그램은 근력 비중이 클 때 위로.
- **미리 묻지 말고 상황이 왔을 때 묻기**: 예) 과식한 날 → 상쇄 카드(이미 구현). 같은 방식을 다른 옵션에도.

## 2. 목적 = 몸 방향(하나) + 시간 비중(막대)
"근비대/근력/감량/유지 중 하나"는 두 질문을 섞은 것 → 분리.

**몸 방향 (하나만)**: 감량 / 리컴프 / 유지 / 증량
- 리컴프 = 유지 칼로리~소폭 적자 + 단백질 높게. 성공 기준을 체중이 아닌 **체지방·제지방·근력 추세**로 표시, 인바디 기록 권장.
- 리컴프는 경력이 길수록 느림 → 설명 문구 대신 예상 속도를 숫자로(중량 프로그램 "목표 현실성"처럼).

**시간 비중 (주간 운동 시간을 나누는 막대)**: 근비대 · 근력 · 기능성 · 스트레칭 · 유산소
- 점수가 아니라 **분** 단위 → 하나를 늘리면 다른 게 줄어든다("다 중요" 불가).
- 웨이트 안에서 근비대:근력 비율 → 반복 범위·무거운 세트 비중. (근력 비중 > 0.6: 주요 3~5회·보조 6~10회 / 0.3~0.6: 주요 3~6회·보조 8~15회 / < 0.3: 6~12회)
- 기능성·스트레칭·유산소 = **추가 블록**. 블록 설정은 빈도 · 시간 · 위치(웨이트 전/후/따로) 세 가지만, 구간을 눌렀을 때 열림.
- 추가 블록이 시간을 먼저 가져가고 웨이트 볼륨이 줄어듦 → 부위당 주 12세트 아래면 막지 않고 경고. (종아리·복근 볼륨 부족 문제도 코어 블록으로 해결 가능)
- 회복: 기능성(케틀벨 스윙·캐리 등)은 관련 부위 볼륨·회복에 일부 반영, 스트레칭은 반영 안 함. 기능성 블록을 켜면 변형·기능성 운동이 추천 후보가 됨.
- 처음 설정: 몸 방향 + 프리셋 버튼(근비대 위주 / 반반 / 근력 위주)으로 막대를 채움. 막대 직접 조절은 MY에서. 기본값 "근비대 위주 + 유지".
- 스트레칭은 운동 목록에 동작이 없음 → 콘텐츠 새로 필요(동작 애니메이션 엔진 재사용 후보).

```ts
plan = {
  body: 'cut' | 'recomp' | 'maintain' | 'bulk',
  weeklyMinutes: 360,
  mix: { hypertrophy: 5, strength: 3, functional: 1, stretch: 1, cardio: 1 },
  blockOptions: { stretch: { freq: 'daily', slot: 'after' }, ... },
  overrides: { 'nutrition.protein': 180, ... },   // 사용자가 직접 바꾼 값, 자동 계산보다 우선
}
effective = { ...presetFor(plan), ...plan.overrides }
```

## 3. 영양 목표: 계속 다시 계산
`deriveTargets(plan, profile, signals) → { kcal, protein, fat, carbs, byDay }` 가 영양 목표의 **유일한 출처**. 오늘·영양 탭·식단 추천·끼니 경고 모두 이 값을 읽는다.

1. **기본(몸 방향 × 제지방량)** — 일반적 연구 범위
   - 유지·증량 ≈ 1.6 g/kg · 리컴프 ≈ 2.0 g/kg · 감량 ≥ 2.2 g/kg, **적자가 클수록·체지방이 낮을수록 더 높게**(마른 사람의 강한 감량은 제지방 kg당 2.3~3.1g 권고 연구 있음)
   - 지방 하한(칼로리 20~25%), 탄수화물은 나머지(웨이트·유산소 시간 많을수록 비중↑)
2. **날마다(옵션)**: 주간 칼로리 예산은 고정, 하체·긴 러닝 날 탄수↑ 휴식일 탄수↓. 단백질은 매일 같게.
3. **매주 보정**
   - 7일 평균 체중 감소 > 주당 체중 1% → 적자 줄이기 제안
   - 감량 중 주요 리프트 e1RM 2~3주 연속 하락 → 근손실 신호, 원인(단백질 평균 %, 적자 크기) 함께 표시
   - 섭취 기록 + 체중 변화로 실제 유지 칼로리 역산 → 목표 자동 수정
   - 리컴프는 제지방·근력 추세가 성공 기준
4. **끼니**: 단백질 적은 끼니가 반복되면 내 식습관 리포트에 한 줄
- 치팅데이·과식 상쇄는 **이미 구현됨**(`src/lib/cheat.ts`·`src/lib/day-target.ts`: 저금통 게이지, 상쇄 기간, 단백질 유지·1.1×BMR 하한). 새로 만들지 않고 `deriveTargets`의 `byDay` 단계로 흡수한다(기본 목표 → 운동일/휴식일 → 치팅·상쇄 조정 순).
- 처음 설정에 건강 안내 한 줄(신장 질환 등은 고단백 주의).

## 4. 코치 엔진 (최상위 조정 계층)
**바닥은 규칙 엔진, 맨 위에만 선택적으로 AI.** (비용·오프라인·재현성/테스트·숫자 안전성)

```
기록(운동·식단·체중·인바디·걸음)
  → 신호층: e1RM 추세 · 7일 체중 추세 · 단백질 평균 · 부위별 회복 · 이행률 (주간 집계 weeklySignals)
  → 코치 엔진: plan + 신호 → Adjustment[]
  → 각 모듈: 오늘 할 일 · 영양 목표 · 식단 추천 · 추가 블록 · MY 그래프
```
```ts
coach(plan, signals, history) → Adjustment[]
// { target: 'nutrition.protein', change: +20, reason, severity, auto: boolean }
```
- 위치: `src/lib/coach/` (신호, deriveTargets, `rules/` 규칙별 작은 파일). 기록 저장·앱 열 때·주 1회 실행, 폰 안에서.
- 각 탭은 계산하지 않고 `useCoach()` 같은 훅으로 결과만 읽음.
- 교차 규칙 예: 감량 중 e1RM 하락 → 단백질↑·적자↓·볼륨 유지 / 무거운 하체 다음날 인터벌 → 러닝 하루 미루기 제안 / 치팅 → 주간 예산 재분배 / 기능성 블록으로 웨이트 시간 감소 → 부족 부위 다른 날로.
- 충돌 우선순위: 안전 > 사용자 직접 설정(overrides) > 목적 > 편의.
- 작은 조정(주간 ±100kcal, 다음 세션 무게)은 자동, 큰 조정은 해당 탭에 한 줄 제안(수락/무시). 모든 조정은 **코치 기록**에 이유와 함께 남고 되돌리기 가능. 자동 조정 끄기 옵션.
- AI(나중, Supabase Edge Function): "왜 바뀌었어?" 설명, 주간 요약, 음식 추정. **숫자는 규칙이 정하고 AI는 설명만.**
- 검증: 가상 사용자 시뮬레이션으로 규칙 테스트.

## 5. MY 탭 (현재 "설정" 탭 → 이름 변경)
> 2026-11-07 1차 구현: 목적 카드(지금의 목표 기준), 추세 카드 4장(주 단위 점, 상태 한 줄, 누르면 세부), 설정 목록, 기능 설명. 아직: 시간 비중 막대·코치 기록·주→날짜 드릴다운.
데이터의 중심은 저장소·코치 엔진이고, MY 탭은 전체를 보고 원본을 고치는 창. 다른 탭은 MY를 거치지 않고 저장소에서 자기 몫을 읽는다.

**구성(위→아래)**
1. 목적 카드: 몸 방향 + 시간 비중 막대 (눌러서 조절, "N개 직접 설정됨")
2. 추세 카드(최대 4장, 목적에 따라 순서 변경): 몸 · 근력(e1RM) · 운동량(부위당 주 세트) · 영양(단백질·칼로리 평균)
3. 코치 기록
4. 세부 설정: 운동 · 영양 · 유산소 · 알림 · 계정 (각 줄에 현재 값 요약)

**거시 → 세부 (터치로 한 단계씩)**
- 첫 화면 카드 = 숫자 하나 + 추세선 하나 + 상태 한 줄. 기간 4주/12주/6개월.
- 카드 터치 → 핵심 세부 3줄 → 그래프의 주 터치 → 날짜별 → 하루 터치 → 기록 탭 하루 타임라인.
- 상태 한 줄 = 코치 엔진의 판단("적정 속도", "목표의 92%"), 색은 초록·주황·빨강만.
- 목표는 그래프 위 띠/점선, 코치 조정은 세로선 → 조정과 결과가 그래프에서 연결.
- 점 하나 = 주간 평균(체중은 7일 평균). 기록 탭 "주간 볼륨"도 같은 weeklySignals를 읽게.

**지킬 규칙**
- 행동은 각 탭에서: 제안은 해당 탭(영양 제안은 영양 탭, 러닝 미루기는 오늘 탭)에 뜬다.
- 수정은 어느 탭에서 해도 같은 `plan`에 저장. 탭만 따로 갖는 값 금지.

## 6. 구현 순서(제안)
1. `plan` 구조를 `src/store/store.ts`에 모으기 (흩어진 목표·볼륨 설정 이전, 기존 사용자 값 마이그레이션)
2. 신호층(`weeklySignals`: e1RM·체중·단백질·세트) + `deriveTargets` (기존 목표 계산·`day-target.ts`·고정식단 차감을 이 안으로 모으기)
3. 처음 설정: 몸 방향 + 프리셋 / MY 탭 목적 카드·시간 막대
4. MY 탭 추세 카드 + 드릴다운
5. 코치 엔진 규칙 + 제안 UI + 코치 기록
6. 추가 블록(기능성·스트레칭 콘텐츠)
- 출시 전 범위는 1~2(+3) 정도, 나머지는 비공개 테스트 피드백 보고 결정.

## 7. 관련 결정
- 다국어 확장: 국가별 별도 앱이 아니라 **한 앱 + 지역별 음식 데이터**. UI 언어와 음식 데이터 지역을 별도 설정(여러 지역 선택 가능). 가공식품 Supabase 테이블(음식 데이터 ②단계)은 처음부터 `region` 필드 포함.
